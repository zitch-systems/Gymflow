# GymFlow approved remediation — 2 October 2026

The changes close the code defects behind all nine P0 findings. Staff privileges now require server-recorded verification bound to the exact live Auth session, and manual/provider payments commit the money, purchased coverage and audit in one transaction. This preserves the existing email/trusted-browser sign-in flow and denies a password-only JWT staff or platform authority.

Cash retries use stable operation and receipt identities. Refunds record explicit amounts: partial refunds retain access, while full refunds remove only unused allocated coverage and preserve other purchased periods. Historic unallocated refunds remain visible for review. Paid terms use inclusive WAT dates and anniversary-minus-one-day calendar ends without rewriting existing paid dates. Frozen legacy subscriptions retain purchased time; allocated full refunds cannot resurrect it on resume. Auto-renewal uses a durable single pending intent and never silently replaces an ambiguous provider mandate.

Reporting now uses proof-gated SQL aggregates, exact roster pages and refund-adjusted revenue. Webhook ingestion, recovery, reconciliation and backups have durable queues, leases, checkpoints and incidents. Health notes have a separate purpose-limited permission boundary. Storage policies, OTP consumption, permission prompts, drawer focus and native stale-data states are corrected.

The root application and Meta connector have zero known production dependency audit findings in their verified locked graphs. The Android export contains the patched runtime parsing dependencies. Its tooling graph retains four high findings from one unpatched Node-only node-forge signing advisory and ancestor chain; CI guards the exact reviewed residual and checks that those signing packages are absent from the Android bundle.

## Verification and release order

The complete PostgreSQL regression suite, web/test TypeScript, lint and production build pass. Focused suites cover payment/refund/freeze concurrency, exact-session privilege denial, OTP consumption, Storage/privacy boundaries, reports beyond the API row cap, recovery queues, connector authentication and Android export compatibility. The precise final test count and deployed commit are recorded by GitHub Actions and the final release evidence.

[PR 245](https://github.com/zitch-systems/Gymflow/pull/245) contains three earlier forward migrations and ten additional migrations in this remediation. CI pins all Actions and installs frozen dependency graphs. After merge, the production order is verify → migrate → live schema fingerprint and catalog audit → production environment validation → build/deploy → HTTP and authorized recovery smoke checks. The connector's independent production Git deployment is verified separately. A preview or an advisory schema-drift pass is not a production migration/deployment certificate.

## Remaining evidence

The native code is committed and its Android bundle is verified; exporting it does not publish a new signed application to the Play Store or update installed binaries. A production restore with actual Auth/Storage data, measured backup throughput/RTO/RPO, physical accessibility/network/permission journeys, and signed-in production/provider test journeys still require recorded evidence. The synthetic isolated restore validates the tooling, not those production claims. There are no raw production backups, customer records or secrets in this report or repository.
