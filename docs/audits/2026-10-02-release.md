# GymFlow approved remediation — 2 October 2026

The changes close the code defects behind all nine P0 findings. Staff privileges now require server-recorded verification bound to the exact live Auth session, and manual/provider payments commit the money, purchased coverage and audit in one transaction. This preserves the existing email/trusted-browser sign-in flow and denies a password-only JWT staff or platform authority.

Cash retries use stable operation and receipt identities. Refunds record explicit amounts: partial refunds retain access, while full refunds remove only unused allocated coverage and preserve other purchased periods. Historic unallocated refunds remain visible for review. Paid terms use inclusive WAT dates and anniversary-minus-one-day calendar ends without rewriting existing paid dates. Freezes restore the full approved elapsed pause whenever paid rights remain, including long pauses and legacy rights; allocated full refunds cannot resurrect revoked coverage on resume. Auto-renewal uses a durable single pending intent and never silently replaces an ambiguous provider mandate.

Reporting now uses proof-gated SQL aggregates, exact roster pages and refund-adjusted revenue. Webhook ingestion, recovery, reconciliation and backups have durable queues, leases, checkpoints and incidents. Health notes have a separate purpose-limited permission boundary. Storage policies, OTP consumption, permission prompts, drawer focus and native stale-data states are corrected. Restrictive Storage guards enforce the tenant and verified-session boundary even when older dashboard permissive policies remain. Their exact predicate, role, command and restrictive mode are compared between the live and shadow databases.

The backup worker runs every fifteen minutes with a twenty-tenant bound, giving 1,920 nominal daily slots; actual throughput and archive size still determine the measured recovery point.

The root application and Meta connector have zero known production dependency audit findings in their verified locked graphs. The Android export contains the patched runtime parsing dependencies. Its tooling graph retains four high findings from one unpatched Node-only node-forge signing advisory and ancestor chain; CI guards the exact reviewed residual and checks that those signing packages are absent from the Android bundle.

## Verification and release order

The complete PostgreSQL regression suite, web/test TypeScript, lint and production build pass. Focused suites cover payment/refund/freeze concurrency, exact-session privilege denial, OTP consumption, Storage/privacy boundaries, reports beyond the API row cap, recovery queues, connector authentication and Android export compatibility. The precise final test count and deployed commit are recorded by GitHub Actions and the final release evidence.

[PR 245](https://github.com/zitch-systems/Gymflow/pull/245) and its release follow-ups contain fifteen forward migrations. CI pins all Actions and installs frozen dependency graphs. After merge, the production order is verify → migrate → live schema fingerprint and catalog audit → hosted production build with environment validation → deploy → runtime HTTP and authorized recovery smoke checks. Vercel's protected secrets cannot be pulled into CI: their placeholder values are rejected, and the hosted build uses the actual protected environment. A scoped audit credential expires after thirty minutes and its project configuration is removed after the probe. Authenticated probes resolve the trusted canonical public origin before sending credentials and reject further redirects. Existing private Config keys are preserved exactly while their classification becomes write-only Secret. The connector's independent production Git deployment is verified separately. A preview or an advisory schema-drift pass is not a production migration/deployment certificate.
