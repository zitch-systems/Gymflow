# GymFlow end-to-end audit — 17 October 2026

## Scope and evidence boundaries

The audit covers the marketing website, member portal, gym administration,
coach portal, platform administration, mobile API, Android/iOS source, and
connected Supabase, WhatsApp and email services.

The baseline is [production/source revision `6a19c74`](https://github.com/zitch-systems/Gymflow/commit/6a19c74).
Remediation is being prepared on
[`fix/end-to-end-audit-20261017`](https://github.com/zitch-systems/Gymflow/tree/fix/end-to-end-audit-20261017).
The initial source inventory contains **83 Next.js page files**, **25 API route
files** and **18 native app TSX route/layout files**. These are source counts,
not a claim that every route has been exercised in a signed-in production
session. Dynamic routes also represent multiple possible records.

Live service observations below were collected on 17 October 2026 around
20:06–20:12 UTC (21:06–21:12 Africa/Lagos). They are read-only observations of
the baseline. Source fixes, local validation, CI results, database deployment
and live release validation must be recorded separately. No customer messages,
payments or production data mutations were initiated by these checks.

## Saved-card remediation

[`20261017201121_restrict_saved_card_credentials.sql`](../../supabase/migrations/20261017201121_restrict_saved_card_credentials.sql)
replaces the broad member policy with owner-only display reads. It revokes
table grants and independently granted column privileges from public,
anonymous and authenticated roles, then grants only the explicit display and
filter columns used by the wallets. Reusable authorization codes and every
write remain service-only. Existing service operations and the explicit web
and native wallet queries are preserved.

[`saved-card-access.test.ts`](../../test/saved-card-access.test.ts) adds 15
PostgreSQL role-based regression cases: owner display access, omitted-filter
isolation, staff denial, direct/wildcard/predicate token disclosure denial,
insert/update/delete/truncate denial, anonymous denial and server processing.
The test TypeScript project compiled successfully during preparation. Actual
database execution is pending CI's PostgreSQL runtime; local type checking
does not certify SQL behavior. No live DDL was applied during the baseline
review.

The source audit also found that the wallets promised automatic saved cards
after payment although no card persistence path was implemented. Web and
native copy are being corrected to describe secure provider checkout without
claiming unsupported card storage.

## Page-by-page web review

All page files in the baseline inventory were reviewed in source. The review
covered 27 admin pages, eight coach pages, 14 platform-admin pages and 34
public/auth/member pages, plus both management CSV exports. The inventory at
end of this report maps every page to its source file.

Confirmed fixes include:

- Member timetable dates now match the future occurrence being booked; booked
  and waitlisted status is specific to the session date. Already-started
  sessions no longer appear as upcoming. Next-class cards use the actual slot.
- Web and native navigation align around Home, Check in, Classes, Wallet and
  Profile. WhatsApp remains reachable from the web profile. Profile figures
  use real data; fictional wallet and referral amounts were removed. Receipt
  sharing works and failures show a recovery path.
- Expired subscriptions can select the same plan to renew. Only owners see
  checkout; coach feature restrictions no longer loop through owner billing.
  Payment callbacks distinguish money received from successful activation.
- Coach/class attendance reports rejected writes and partial saves, excludes
  cancelled sessions, and preserves waitlist status. Payout rejection now
  allows a reason before explicit submission.
- Superadmin pagination respects the configured console path; searches happen
  before pagination and use exact KPI totals. Invalid page/date input recovers
  safely. Wallet and expense sums use bounded complete reads and fail visibly
  at their limit instead of silently undercounting.
- WAT dates/times are consistent, rejected payouts do not inflate pending
  earnings, expense input supports naira/kobo amounts, and mobile layouts,
  navigation semantics, pending states and image-operation locks are improved.
- Console error boundaries preserve navigation and offer retry. Primary data
  failures are not presented as empty rosters, attendance or payment records.
- Public pricing durations and billing-cycle copy are consistent. Light-theme
  hero preview and header buttons have readable foreground colors.

Live browser checks on the baseline covered home, pricing (annual toggle and
FAQ expansion), features, about, contact, gallery, careers, legal and the login
entry. No application console error was seen in those checks; browser-extension
metadata errors were excluded. Signed-in production browser journeys were not
available and are not claimed as tested.

## API and native review

The mobile API review covers authentication, active-gym selection, profile,
classes, check-in, notifications, plans, renewal, wallet/receipt and account
deletion boundaries. Data-query failures return a retryable response rather
than false no-membership or empty-success payloads. Profile input rejects
invalid calendar dates. Attendance updates validate status and actual affected
rows, with coach/gym scope retained.

Class bookings preserve one record per occurrence and historical cancellation
or attendance. The database capacity trigger counts all members under its
existing transaction lock; clients display its committed booked/waitlisted
status. A new partial uniqueness rule prevents duplicate active seats without
rewriting history. Capacity and repeat-booking changes must be deployed after
their database migration, as enforced by the existing main CI sequence.

Native source review covers every tab and route: authentication, Home, Classes,
Check in, Wallet, Profile, profile edit, notifications, receipt, renewal and
account deletion. Fixes include gym-specific QR/link validation, matching
occurrence dates, full notification reading, safe-area spacing, mutation locks,
retry controls, malformed-response/network timeouts, session refresh failure
handling and stale-resource cleanup. App version is 1.0.1, Android versionCode 2,
and iOS buildNumber 2.

Configured waiver document rendering and acceptance are being aligned across
web and native using the existing signature records; no historical acceptance
is backfilled. The live baseline had no configured waivers or signatures.
Physical-device camera/permission checks and real payment/OTP journeys still
require separate acceptance evidence. An Android export or simulator build
alone is not a physical-device or App Store release certificate.
