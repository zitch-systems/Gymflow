# GymFlow audit — 28 October 2026

## Scope and outcome

Inspected public web navigation and forms, native member screens, shared membership/payment rules, WhatsApp configuration and receipt handling, production database health, scheduled jobs, and dependencies. This is not certification that every production journey works. Signed-in browser acceptance, real-device journeys and a successful live WhatsApp send remain unverified.

## Fixes

- Native membership screen: freeze requests, pending/frozen states, explicit auto-renew cancellation. Shared web/native date, ownership, gym and concurrency checks prevent false success and duplicate notices.
- Native renewal now supports explicit opt-in recurring billing through the same reservation, pricing and duplicate-mandate guard as web. One-time remains default. Changing the trainer price resets consent. Stale data cannot start checkout; callback text cannot by itself claim payment confirmation.
- Native documents/waiver and gym WhatsApp entry are accessible directly from Profile. Profile writes verify a saved row, hide internal DB errors and prevent duplicate taps.
- Web profile surfaces query failures instead of showing fabricated empty data.
- WhatsApp delivery receipts cannot regress read/delivered state; successful delivery clears stale errors; failed database writes surface as errors. Strict signature parsing and malformed-payload handling have regressions.
- Meta connector distinguishes omitted event-field data from an explicit empty list.
- Feature-page class reminder copy now describes the implemented morning email digest; waitlist promotion wording corrected.
- Next.js and matching ESLint config updated to 16.4.3. Meta SDK updated to 1.32.2 and Zod to 4.6.7, with bounded MCP validation. Expo CLI Zod patched with actual schema compatibility checks.

## Verification completed locally

- 882 tests in 71 non-database test files passed. Full PostgreSQL 17/RLS suite requires CI; no local database server available.
- Web production build, TypeScript and lint passed.
- 74 native component checks across all 20 route/layout files passed, including healthy/loading/error/stale states and meaningful mutation interactions. Native platform and API boundaries are mocked; these are not device UI tests.
- Native type/lint, auth/refresh/routing, QR/date/resource/waiver contracts passed.
- Android and iOS JavaScript/Hermes exports passed; both source maps exclude the reviewed vulnerable Node build packages.
- Meta connector: type/build and 6 tests passed, including real SDK/schema integration and oversized-input refusal.
- Web and connector production dependency audits report no known vulnerabilities. Mobile tooling retains 1 high (node-forge) and 7 low (deepmerge chains), no moderate/critical findings. Exact reviewed chains are documented and excluded from the shipped bundles; build-environment risk remains.
- Live desktop browser: home, pricing cycle/FAQ, features, contact required-field validation, about, gallery, careers, legal sections, sign-in/registration navigation. Observed public pages had no horizontal overflow or broken loaded images. No contact message or account was submitted.
- Existing live mobile API boundary smoke passed: deletion entry, protected profile/waiver/deletion, empty refresh validation and CORS. New membership route requires post-deploy verification.

## Production observations and outstanding acceptance

- Supabase is healthy; all 70 public tables have RLS enabled. Four scheduled jobs showed recent success and zero consecutive failures.
- Seven payment incidents and two dead webhook jobs remain unresolved. Do not change financial records without provider/reference evidence.
- WhatsApp credentials and WABA subscription respond successfully; published member Flow has no validation errors; five inspected templates approved. The configured phone reports expired code verification and declined display name. Most recent logged outbound failure is business eligibility related. Empty returned event fields do not prove missing app subscriptions. Actual send/delivery requires Meta account remediation and an explicitly designated test recipient.
- Leaked-password protection is disabled in Supabase; enabling it remains an account configuration task.
- No real customer messages, payments, deletions or membership changes were performed during the audit.
- No signed-in member/staff/coach/superadmin browser journey or physical Android/iPhone acceptance was completed. Native UI checks and bundles do not prove camera, deep-link banking handoff, accessibility or every device layout.
- Native version is prepared as 1.0.2 / build 3. CI native compilation, emulator/simulator smoke, APK publication and production deployment are separate release gates.
